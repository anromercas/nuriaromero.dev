# 0013. SEO site architecture: one owner page per keyword cluster

- Status: Accepted (2026-11-15, PO on accepting NRD-74; proposals P1 and P2 remain "Pendiente de la usuaria")
- Date: 2026-11-15

## Context

SEO method phase 3 of 8 (epic NRD-4, story NRD-74). The user's first SEO priority is keyword targeting of the service pages, and reworking the structure if it is wrong, before any page rewrite (phase 5, NRD-76) or link building (phase 7, NRD-72). NRD-22 measured the 24 URLs, NRD-73 and NRD-97 grouped the Seville queries of six services into clusters, NRD-98 diagnosed indexation. This ADR turns those inputs into one decision: which page owns which cluster, what each existing page is (keep, re-target, merge, split, create), how the pages link to each other, which URL changes follow, and in what order phase 5 should work.

The ADR names changes; it never applies them. No `src/**`, `public/**`, test or script file changes in this story. Ownership of a term keeps the rule of ADR 0012: one owner page per head term, and only the owner targets it in `<title>`, H1 or H2.

Conventions: analysis in English, queries and page copy in Spanish verbatim. **Dato observado** is a figure with its source and date; **Inferencia** is a reading of those facts. "gap" means not measured and "sin dato (...)" means the tool returned no value; neither is 0 and no figure here is estimated. Source ids S1 to S10 are those of `docs/seo-audit/keyword-clusters-2026-11.md` ("Fuentes reutilizadas"). Volumes are Spain-level monthly searches; Search Console figures are impressions and average position in the single 28-day window 2026-10-16 to 2026-11-12 (web, Spain, all devices), so every conclusion is directional.

## Decision

One owner page per in-focus keyword cluster, mapped below. The decision is **adjust**, not rework (verdict line and reasons below). Three kinds of statement are kept apart:

- **decided**: the owner is an existing URL that fits the evidence; the per-page story can start.
- **provisional**: the owner is proposed and still stands, but one named input is weak or missing; the per-page story re-checks that input first.
- **pending the user**: creating a page or a service is radical (PRD section 9); the row is a proposal with options and a recommendation in "Propuestas pendientes de la usuaria" and nothing is applied until the user approves it in the PRD decision log.

**Link rules.**

1. **Spoke to hub.** Every post links its hub once, in the body or in the closing block, with a descriptive Spanish anchor that matches the hub's cluster (examples already in the data: "servicio de SEO local y GEO", "servicio de diseño web y su alcance"). A post whose cluster has no in-focus hub (the restaurants post, parked niche) links the closest in-focus hub.
2. **Hub to spoke.** A hub links each of its spokes once, kind `contextual`, with an anchor that names the guide, not the hub's own service ("guía para mejorar tu ficha de Google Maps").
3. **Hub to hub.** Sibling service pages link each other only where the intents are adjacent: design with tienda, design with software, software with automatizaciones and IA, automatizaciones with IA, seo-local with design. Not every pair; no site-wide link grid.
4. **Pointer from the wrong page.** When a page earns impressions for a cluster another page owns (`aplicaciones web a medida sevilla` on `/diseno-web-sevilla/`, TO-3 on both SEO and design pages), the fix is a contextual link to the owner, not a copy of the owner's content (inventory recommendations 4 and 8).
5. **Conversion links.** Each commercial page keeps one `conversion` link to `/contacto`; posts keep theirs. No change here.
6. **Reciprocal pairs.** A hub and spoke or two sibling hubs that must link each other are recorded in `reciprocalLinks`, so `scripts/check-seo-07.mjs` fails if one direction disappears.

**Anchor policy.** Anchors are descriptive Spanish phrases that match the owner cluster of the page they point to. An exact-match anchor is allowed only toward the owner of that term (`consultor SEO en Sevilla` toward `/`, `SEO local y GEO en Sevilla` toward `/seo-local-sevilla/`). A page never repeats another page's registered term as an exact-match anchor, heading or H2 target (ADR 0012), and never repeats the same anchor text for two different targets. Audit of the 16 sources in `internalLinksBySource` on this branch: no current anchor breaks the rule, so the spec below only adds or edits rows for the reasons given.

**Weak pages (inventory recommendations 4 and 6).** `/desarrollo-software-medida/` has 2 inbound links from `<main>` (`/` and `/automatizaciones/`, NRD-22). It gains two sources: `/diseno-web-sevilla/` (for "aplicaciones web a medida", the 67 misrouted impressions of SW-1) and `/inteligencia-artificial/`, so it reaches 4. `/portfolio/` has 1 inbound (`/recursos/`) and is reachable from `<main>` of no service page; it gains `/diseno-web-sevilla/` and `/` (3 in total). `/recursos/` (1 inbound, from `/`, short by design, "URL is unknown to Google", no intent in `intentMatrix`) gets **no change**: it owns no cluster, so more links would be links for their own sake; requesting its indexation is an owner action (NRD-98, "Acciones en Search Console", step 5). `/blog/pagina-web-para-restaurantes-que-necesita/` gains a link to its in-focus hub (see below) but not a link from a hub, because it feeds a parked cluster.

### Verdict

Veredicto: adjust

- **The structure already fits the evidence.** 12 of the 14 clusters have an existing URL as owner (9 service or home pages, 3 posts); only GEO-1 and DW-3 need a new page, and both are proposals for the user (P1, P2), not part of this verdict (owner map).
- **No URL needs to change.** The two ownership conflicts that NRD-73 flagged are resolved by data: `consultor seo sevilla` stays on `/` and the registered `diseño tienda online sevilla` stays on `/tienda-online-sevilla/` (NRD-34, accepted 2026-11-13). No 301 row, no sitemap or `llms.txt` change (URL changes).
- **The mismatch is demand capture and routing, not page set.** `/seo-local-sevilla/` has 76 impressions for its brand head `seo local sevilla` but none for `agencia seo sevilla` (1,000 searches) and `posicionamiento web sevilla` (320); `/diseno-web-sevilla/` has 4 impressions for `diseño web sevilla` (880) against 145 and 94 for two variants; 67 of 76 software impressions land on the design page (S7, S1, window 2026-10-16 to 2026-11-12). These are title, H1, H2 and link decisions per page, with data rows in the spec above.
- **Indexation, not architecture, blocks measurement.** Two in-focus pages (`/tienda-online-sevilla/`, `/inteligencia-artificial/`) are "URL is unknown to Google" and three posts are "Crawled - currently not indexed", and NRD-98 found no site cause on any of them. A URL rework would not change that (NRD-98, 2026-11-15).
- **What would flip the verdict to rework.** Not the current evidence: a rework would need data that is missing (competitor word counts, exact-head SERPs, indexed owner pages) or a user decision on P1 or P2. The provisional clusters are re-checked in their per-page stories, and a changed reading is recorded in a new ADR that supersedes this one.

## Consequences

- **Easier.** One reviewed map says which page may target which term; `seo-review` can check a diff against the registry plus tables A to D. Phase-5 stories start from decided or provisional rows instead of re-deriving ownership.
- **Harder.** The registry grows from 5 to 10 terms, so more H2 overlaps will be flagged to the PO (ADR 0012). Seven clusters are provisional and each per-page story must re-check its named input first.
- **NRD-75 (technical SEO review limited to what this ADR changes).** Scope: no URL change, so no redirect or sitemap work except `/seo-para-ia/` if P1 is approved; the blog trailing-slash bug and its JSON-LD `item`; `public/llms.txt` consistency when a page is added; `pnpm check:seo-07` with the new rows.
- **NRD-76 (checklist and per-page stories).** Create the stories in "Orden de optimización"; each takes from this ADR its owner cluster(s), registered terms, link rows, provisional input to re-check and status (decided, provisional, pending the user). The SEO and GEO checklist is NRD-76's own deliverable.
- **NRD-77 (local signals).** Align Google Business Profile, NAP citations and review cadence with the owner pages of the clusters whose SERP has a local pack: SL-1, SL-2, DW-1 and SW-1 (S1, S2, S3, S10). GEO-1, DW-2, IA-2 and TO-3 have no local pack.
- **NRD-24, NRD-25, NRD-26 (`/seo-para-ia/`).** The URL is a placeholder until D2; the page owns GEO-1 only, not GEO-2 or GEO-3; NRD-25 adds the `intentMatrix` row (national scope), links rows 8 to 11, the `llms.txt` entry and the `keywordOwners` row; all of it waits for P1 and D1-D4.
- **Redirect stories.** None are created: the redirect table is empty.
