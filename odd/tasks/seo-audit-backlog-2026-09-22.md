- **SEO-17 (2026-09-22):** Fixed `src/components/WhatsAppButton.astro`. Approach chosen: hide the fixed floating WhatsApp button (via `display:none`, not just opacity) while the home hero's own CTA nav (`[data-seo12-primary-cta]`, which already includes an inline "Cuéntame tu negocio por WhatsApp" CTA) is in the viewport on mobile (`matchMedia("(max-width: 767px)")`), using an `IntersectionObserver` — chosen over widening hero spacing because the floating button is `position:fixed` (its viewport-space position doesn't move with content padding, so a spacing fix couldn't guarantee zero overlap against future hero-copy changes), and because the button is genuinely redundant while the hero's own WhatsApp CTA is visible. No prior scroll/IntersectionObserver logic existed in the codebase to extend, so this introduces the first one, gated defensively (`if (!floatingButton || !heroCta || !("IntersectionObserver" in window)) return`) so it's a no-op on pages without `[data-seo12-primary-cta]` (i.e. every page except the home) and in unsupported browsers (button just stays visible as before, no regression). `display:none` was chosen over `opacity:0` specifically so `getBoundingClientRect()` collapses to a zero-size box (no layout box at all) — an opacity-only hide would still geometrically intersect the CTA per raw DOM rects, even though invisible/non-interactive. Home page and other components (`Hero.astro`, `index.astro`) untouched.
